## Leanstral task mismatch (do not forget)

Leanstral 1.5 (119B-MoE / 6.5B-active, Apache-2.0) is trained as a
*proof agent*: multiturn compiler loop given a theorem statement,
plus a filesystem code-agent; Mistral’s path is Vibe +
`lean-lsp-mcp`. Advertised scores (miniF2F 100%, Putnam 587/672)
are proof-generation on already-formal statements.

Our `formalize` call is one JSON request: accepted EI →
`{statement, target_theorem, mapping_report}`. No LSP, no goal
state, no file edits. Using Putnam/Kimina/Goedel/Pythagoras numbers
to pick a formalizer optimizes the wrong leaderboard.

Free hosted alternatives that emit our mapping-report contract:
**none.** Kimina / Goedel / Pythagoras are open *provers* (weights,
no free API). medium-3.5 is the right *job shape* for
statement+mapping (already paid). Standing next step: **dev-fixture
A/B** (leanstral vs medium-3.5 vs small-4), prediction-first, spent
holdouts untouched. Reserve leanstral for a later proving/repair
path *if* we add interactive Lean (Agentic, not Intelligence).

## `opinion` (proposed, not implemented)

Consultative side-door. Never writes a lifecycle transition.
`opinion --claim-id --on ei|formal|bundle` →
`artifacts/local/a3/opinions/<id>/rev-N.json` +
`EVENT_DIAGNOSTIC_RESULT` only. Schema: P1–P6 +
`recommended_decision` (advice, not `review.decision`). Capability
`SEMANTIC_TRIAGE` (medium-3.5). Distinct from existing
`review --reviewer-kind ai`, which *can* emit `ACCEPTED`.
Refused from `DRAFT` / `REJECTED`. Empty clarify ≠ consent to add
the subcommand.
