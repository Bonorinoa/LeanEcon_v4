## Narrowed promise (what this tag, when fired, claims)

LeanEcon is a **verifiable state machine** for a single economic claim.

1. Every claim walks an explicit lifecycle
   (`DRAFT → INTERPRETED → REVIEW_REQUIRED → ACCEPTED → FORMALIZED →
   PROVING → VERIFIED`) with honest `FAILED` / `BLOCKED` exits.
   New failure paths update `lifecycle.TRANSITIONS` in the same change.
2. Live `formalize` is a **transition** of that machine: the bounded
   kernel-feedback loop (`revise_loop`, budget 3) runs on the live
   path; exhausted budget writes no formal artifact; provider outage
   is `BLOCKED`, not an attempt.
3. `skeleton` is a drafting side-door. Unresolved `-- GAP:` cannot
   enter `verify`.
4. `VERIFIED` is emitted only by the 12-check bundle validator plus
   the kernel axiom audit (`#print axioms` / `sorryAx` absent).
   Compile exit 0 is not a pass.
5. Meaning stays reviewer-owned (human or AI). Models may draft
   interpretation and formalization; they do not self-certify.
6. Draft quality is **measured** (fixture scorer + sealed holdout
   protocol) and is **not** part of this tag's product claim.
   Combined held-out draft-complete is **2/13 ≈ 15%**. Sole-author
   of `VERIFIED` is **0%**.

This is a narrower promise than INIT_V3's original "constrained
auto-formalize at 60–70% draft-complete." The machine is the product.
The intelligence that drives some of its transitions is v4 work.
